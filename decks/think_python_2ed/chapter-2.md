Q: What is a variable?
A: A name that refers to a value.

Q: What does an assignment statement do?
A: Creates a new variable and gives it a value.

C: A [state diagram] is a graphical representation that shows what state each variable is in by writing the variable name with an arrow pointing to its value.

Q: What are the rules for variable names in Python?
A:
- Can be as long as you like
- Can contain letters and numbers, but can't begin with a number
- Can use uppercase letters, but conventionally use only lowercase
- The underscore character (_) can appear in a name

C: The [underscore] character can appear in variable names and is often used in names with multiple words.

Q: What happens if you give a variable an illegal name?
A: You get a syntax error.

Q: Why can't you use "class" as a variable name?
A: It is one of Python's keywords, which the interpreter uses to recognize the structure of the program.

Q: What is an expression?
A: A combination of values, variables, and operators. A value by itself or a variable by itself is also considered an expression.

Q: What does it mean when the interpreter "evaluates" an expression?
A: It finds the value of the expression.

Q: What is a statement?
A: A unit of code that has an effect, like creating a variable or displaying a value.

C: When you type a statement, the interpreter [executes] it, which means it does whatever the statement says.

Q: What is the difference between interactive mode and script mode?
A: Interactive mode means you interact directly with the interpreter by typing code at the prompt. Script mode means you save code in a file (script) and run the interpreter to execute the script.

Q: What is a key difference in how expressions behave in interactive mode versus script mode?
A: In interactive mode, an expression displays its result automatically. In script mode, an expression by itself has no visible effect - you need a print statement to display the result.

Q: What file extension do Python scripts conventionally use?
A: .py

C: The acronym [PEMDAS] is a useful way to remember the order of operations.

Q: What is the order of precedence for Python operators (from highest to lowest)?
A:
- Parentheses (highest)
- Exponentiation
- Multiplication and Division
- Addition and Subtraction (lowest)

Q: In what order are operators with the same precedence evaluated?
A: From left to right (except exponentiation).

Q: What two mathematical operators work on strings?
A: + (concatenation) and * (repetition).

C: The [+] operator performs string concatenation, which means it joins strings by linking them end-to-end.

Q: What does the * operator do with strings?
A: It performs repetition. For example, 'Spam'*3 is 'SpamSpamSpam'.

Q: When using the * operator with strings, what type must the other operand be?
A: An integer.

Q: What are comments in Python and how are they indicated?
A: Notes added to programs to explain in natural language what the program is doing. They start with the # symbol.

Q: What happens to text after the # symbol in Python code?
A: Everything from the # to the end of the line is ignored - it has no effect on the execution of the program.

Q: What are the three kinds of errors that can occur in a program?
A: Syntax errors, runtime errors, and semantic errors.

Q: What is a syntax error?
A: An error in a program that makes it impossible to parse (and therefore impossible to interpret) because it violates the structure rules of the language.

Q: What happens when Python encounters a syntax error?
A: Python displays an error message and quits, and you will not be able to run the program.

Q: What is a runtime error?
A: An error that does not appear until after the program has started running. Also called an exception.

C: Runtime errors are also called [exceptions] because they usually indicate that something exceptional (and bad) has happened.

Q: What is a semantic error?
A: An error in a program that makes it do something other than what the programmer intended. The program runs without error messages but doesn't do the right thing.

Q: Why are semantic errors tricky to identify?
A: They require you to work backward by looking at the output of the program and trying to figure out what it is doing.
